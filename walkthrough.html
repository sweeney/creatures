Reverse engineering · 16-bit NE · Delphi 1

Reading CREATURE.EXE

A 1996 Windows teaching program, and how its predator–prey model was recovered from 16-bit code that carries no symbols — the file format, the way in, and the algorithm as the binary actually runs it.

Subject: Creatures 1.0, Future Skill Software · author H M Sauro
01

The executable is not the program

creat.exe is 541 KB and refuses to be a Windows binary. Its header says MZ, then immediately says something more useful:

Inside is the actual program: CREATURE.EXE, 692 KB, 16-bit NE — a Windows 3.x binary — along with an installer, a settings file, and six saved fields with the extension .FLD. The strings give away the toolchain immediately: Borland Delphi, Portions Copyright (c) 1983,95 Borland. Delphi 1, the only version that emitted 16-bit code.

That matters more than it sounds. Delphi stores each form as a serialised resource, and those decode losslessly — every control, its geometry, and the name of every event handler. The compiled Pascal is gone, but the program's entire skeleton is recoverable, and with it a labelled index of its own behaviour: FieldonScreenPaint, DisasterTimerTimer, btnStartClick.

02

The saved fields

Each .FLD is exactly 6930 bytes and starts with a Pascal string, CPATTERN1. After it sit twenty IEEE doubles, then three counts, some flags, a size — and then the field itself.

offsetsizemeaning
010Pascal string CPATTERN1
1016020 × float64 parameters
1706uint16 rabbits, foxes, grass
1769display and print flags
1853graph scale, graph on/off
2042field size N — 50 or 80
206672482 × 82 grid of cells

The grid is a fixed array[0..81, 0..81] of Byte written wholesale, so the row stride stays 82 even when the live field is 50 × 50. That single detail is what breaks a naive parser, and it is the fact that later makes the engine findable.

The twenty doubles line up exactly with the shipped STARTUP.INI, which is how the mapping was confirmed rather than guessed. Cells are a bitfield: 1 grass, 2 rabbit, 4 fox — so 3 is a rabbit standing on grass. A reader and writer round-trips all six shipped files byte-identically, and independently reproduces the population counts stored in each header.

The sample fields are unit tests

Six .FLD files ship with the program, and four of them have reproduction arrays with a single non-zero entry. FISSION.FLD allows a rabbit to breed only when it has eight free neighbours — total isolation — and starts with one rabbit in an otherwise full field of grass. SEX.FLD allows it only at seven free neighbours, meaning exactly one neighbour, and starts with fifteen rabbits, each isolated. RADIO.FLD sets every reproduction probability to zero and raises the death rate, leaving pure exponential decay with a half-life of about 3.5 generations.

Each one isolates a single mechanism: asexual division, sexual reproduction, decay. They are diagnostic instruments, and they are the fastest way to check any reimplementation — a model that cannot make FISSION.FLD grow past two is missing something, whatever its population statistics say.

03

Getting into the binary

CREATURE.EXE has nineteen segments, 311 KB of 16-bit code, and no symbols. Two things make it navigable.

Delphi hands you the entry points

A form resource says OnTimer = Timer1Timer, and Delphi resolves that by name at load time. So every published method sits in the class's method table as an address followed by its name. The address is stored as the NE relocation placeholder FF FF 00 00 and patched at load, so the walk is: name → relocation record → entry table → code.

The form settles what the program looked like

The same resources give the full control list, which is worth having because the surviving screenshots do not agree with the binary. The shipped form carries five sliders — sunlight, grass death, fox hunting ability, rabbit death, fox death — and no control for simulation speed, which is set from the Speed menu alone. The widely circulated screenshot shows a sixth slider labelled Simulation Speed.

Neither is wrong; they are different builds. The screenshot is the later one. It is a useful reminder that a program has versions, and that a picture of it is evidence about one of them rather than about the artefact you happen to be holding.

The program documents its own central rule

One of the eight forms is the configuration dialog, and its help text states the mechanism at the heart of the model in the author's own words — recovered as plain text, before a single instruction had been read:

The likelihood of a rabbit reproducing depends on the number of free squares around the animal. The array below shows the current probabilities for the eight possible patterns of vacancies.

That is a complete specification of one rule: a nine-entry table indexed by how many of the eight neighbouring cells are empty. It named what to look for in the disassembly long before there was any hope of finding it, and the machine code later confirmed it exactly — a routine that counts free neighbours, feeding a table lookup.

The automaton has a fingerprint

The field is 82 bytes per row, and 82 is not a number that turns up by accident. Every index into the grid compiles to a multiply by 0x52. Counting them across all eighteen code segments:

04

What the data segment says

Before reading any code, the data segment gives up the model's vocabulary. Three 82 × 82 buffers sit contiguously 6724 bytes apart, and the cell values are laid out in a row:

addressnamevalue
DS:021ABORDER0xA0
DS:021BEMPTY0
DS:021CGRASS1
DS:021DRABBIT2
DS:021EFOX4
DS:021FDISEASED8
DS:0224ANIMAL_MASK0x0E
DS:0226FIELD_SIZE50

0xA0 is 1010 0000 — chosen so that a border cell reads as no grass, no rabbit and no fox under a plain bit test. The border needs no special case because its value already answers every question correctly.

The parameters sit at DS:0228 on a sixteen-byte stride as (value, max) pairs, in exactly the order STARTUP.INI lists them — which is what the INI loader writes into. The nine reproduction probabilities follow at DS:0280, matching the INI byte for byte.

05

The generation

DoGeneration runs four passes over the field. Every pass reads one buffer and writes another, with an explicit commit between — the update is double-buffered, not in place.

Grass only ever spreads from existing grass — a cell with grass rolls against sunlight, and on success picks one random neighbour that isn't already grass and colonises it. Nothing makes grass appear spontaneously. A fox has no separate reproduction step at all: catching an adjacent rabbit is reproduction, and the cub takes the prey's cell. Reproduction for rabbits is gated on grass at the parent — the trophic link that ties sunlight, through grass, to the animals above it.

And then there are the details that only the instructions give up.

Movement is four-way, and half the time

The engine draws Random(8) for a direction — but the dispatch is a compare chain testing only 1, 3, 5 and 7. There are no diagonal moves, and movement happens at most half of the time. Every path that does not move — an even draw, a border, an occupied square — falls through to a write that puts the animal back in its own cell, which matters because the grass pass has already overwritten that byte.

Reproduction, a few hundred bytes away, uses a real eight-way jump table. The author plainly knew how to write one — which makes the four-way movement read as a decision, not an oversight.

Grazing is one in fifty

A rabbit does not eat the grass beneath it each generation. It draws Random(50) and grazes only when the result is exactly 25.

The move itself is written in a way that produces two side effects the author may not have intended, but which are unambiguous in the code:

The animal "moves" only because nothing writes it back at the source. The value written to the target is composed from the source's pending ground state — so grass travels with a moving animal — and it is a mov, not an or, so whatever grass was already at the target is destroyed.

Elsewhere the same shape appears as a plain dead store: the disease pass writes CUR[nb] AND NOT RABBIT to a cell and then immediately overwrites the same address with CUR[nb] OR DISEASED. Only the second write survives. In AddDiseasedRabbit the two writes are separated by a read-back, so both take effect — and the newly infected rabbit loses its rabbit bit, quietly dropping out of the population count.

06

The disasters

The Disasters menu never touches the field. Each item changes a single parameter; three of the four save the old value first so a timer can put it back. They are temporary shocks to the model, not damage to the grid.

menu itemeffectreverts
Fire destroys grassGrassDeathRate := 0.79yes
Disease spreads through rabbitsRabbitDeathRate := 0.5yes
Over hunting of foxesFoxDeathRate := 0.75yes
Asteroid hits earthSolarEnergyInput := 0.175no

The asteroid is the odd one only in being permanent: it changes sunlight with no saved value and starts no timer, so the Sunlight slider stays where the disaster put it and the user has to drag it back.

All four move their parameter's slider, and three of them get the arithmetic wrong. The asteroid computes the position as value × 100 / max; fire, over-hunting and disease multiply by the maximum instead of dividing. That is only the same operation when the maximum is 1.0, which is true of GrassDeathRate alone — so fire comes out right by luck and the other two do not. Over-hunting compounds it by reading grass's maximum rather than its own.

The parameter itself is always set correctly, so the simulation never diverges; only the number under the slider is wrong. And both broken cases push a parameter past its own slider ceiling — a fox death rate of 0.75 against a maximum of 0.5 — so the correct reading would be 150%, off the end of the track. There is no right answer to display, which is plausibly why nobody noticed.

There are four disasters, not five. The item captioned "Asteroid hits earth — dust in atmosphere" is the component NuclearWinter1, so its handler is NuclearWinter1Click. The caption was changed at some point and the name never followed it.

08

Built to be checked

The transcribed model is now a few hundred lines of dependency-free JavaScript with a test for each rule, including the ones that only exist because the binary says so: that Random(n) returns 1..n rather than 0..n-1; that the eight neighbours are scanned N, NW, W, SW, S, SE, E, NE, which decides where a given random draw sends an offspring; that even movement draws are no-ops.

What stands out, thirty years on, is how much of the program is built to be checked. The file format carries its own population counts, so a corrupt field announces itself. The border sentinel is picked so the edge case evaporates rather than needing a branch. The parameters sit in value-and-maximum pairs, so a slider cannot put the model somewhere it should not go. And the sample fields each disable everything but one mechanism.

That last one is the tell. Those files are not demonstrations, they are experiments — the same kind you would write today, and the fastest way to check any reimplementation. Whoever made them was testing this model from the other side of it.
